# archive/ — Archived Files

> 中文版：[README.md](./README.md)

This folder holds files that are **not part of the portfolio showcase but are kept for historical traceability**. Nothing here appears in the root README navigation or is presented as a project.

## What is archived

| Path | Description | Origin |
| --- | --- | --- |
| `src_my_project/my_project/` | An early scaffold package generated by `uv init` (a single `__init__.py` with a `main()` stub); no business logic | former root `src/my_project` |
| `pyproject.toml` | Project config for that scaffold (package name `my-project`, auto-generated placeholder description) | former root `pyproject.toml` |
| `uv.lock` | Lock file for that scaffold | former root `uv.lock` |
| `.python-version` | Python version pin for that scaffold (3.14) | former root `.python-version` |

## Why `archive/` instead of `projects/`

`projects/` only contains **showcaseable projects with real business value**. `src/my_project` is an empty `uv` scaffold with no business logic, so:

- **Not deleted** — keeping it preserves the historical record of the original scaffold in Git history;
- **Not in `projects/`** — so the portfolio navigation stays clean and meaningful;
- **Config files archived together** — `pyproject.toml` / `uv.lock` / `.python-version` all pointed at `src/my_project`. Moving only the source would leave orphaned config at the root, so they were moved into `archive/` as well to keep the archive self-consistent and the root tidy.

> If a real Python project is needed later, regenerate a fresh `pyproject.toml` at the root rather than restoring these archived files.
